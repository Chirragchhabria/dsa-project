# Public datasets for alert correlation

Checked 2026-11-04 against the publishers' pages. The current CLI expects `event_id,timestamp,source_ip,destination_ip,username,hostname,event_type,severity,description,source,scenario_label`; none of these sources is a direct drop-in. An adapter must preserve original labels separately from fields used by correlation.

## Recommendation

The initial CSE-CIC-IDS2018 recommendation was superseded after inspecting the actual processed CSV: its 14 February 2018 file has `Timestamp` and `Label` but **no source or destination IP columns**. It therefore cannot drive the current entity-based correlation rules without fabricating entities.

Use [CIDDS-001 from Hochschule Coburg](https://www.hs-coburg.de/forschen/cidds-coburg-intrusion-detection-data-sets/) for the first 10,000-row pilot. Its internal OpenStack flow CSV has `Date first seen`, `Src IP Addr`, `Dst IP Addr`, `class`, `attackType`, and `attackID`. The latter provides attack membership labels suitable for a limited pairwise grouping test. The source archive is 384 MB; `scripts/prepare_cidds.py` reads only the needed ZIP member via HTTP ranges or a local archive and writes a deterministic balanced sample. Source data should remain outside the repository pending redistribution permission.

Do not download a full corpus into this repository. Keep the existing synthetic presentation dataset for the classroom demo until the external-data adapter and evaluation method are verified.
